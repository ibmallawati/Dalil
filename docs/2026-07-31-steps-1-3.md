## 1. Context for this revision

D1 was originally "consolidate entirely on OpenAI." That was revised mid-implementation
under two new constraints:

- **Hard $0 budget.** No paid service anywhere in the project.
- **Hosting is no longer a constraint.** A teammate owns deployment; worst case the
  demo runs on `127.0.0.1`.

The second constraint voids the "no `sentence-transformers`, no torch" lesson inherited
from `Chatbot-Public`. That rule existed *only* because torch blew past a free host's
image-size limit. With hosting off the critical path, the reason is gone and the
embedding model can run locally — which is also what makes it free.

### Resulting architecture

Two model workloads, deliberately split:

| Workload | Where it runs | Configured by | Network? | Cost |
|---|---|---|---|---|
| Generation | remote, OpenAI-**compatible** endpoint | `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | yes | free tier |
| Embeddings | **in-process**, sentence-transformers | `EMBED_MODEL`, `EMBED_DIM` | **no** | free |

Generation is provider-neutral on purpose: Gemini's free tier today, a local Ollama
server (`LLM_BASE_URL=http://localhost:11434/v1`) as the offline demo-day fallback.
Swapping between them is a `.env` edit, never a code change.

The retrieval path never touches the network. It cannot rate-limit, cannot time out,
and cannot fail because a token expired on the morning of a demo. The only remote call
left in a request is generation.

## 3. The finding that matters

e5 was run live against a stand-in ROP/MoCIIP corpus: 6 Arabic service passages,
10 real citizen questions, 6 out-of-domain questions.

```
                   top-1     in-min   out-max        gap
correct prefixes    9/10     0.7968    0.7816    +0.0153
no prefixes         9/10     0.8011    0.7901    +0.0110
swapped prefixes    8/10     0.8217    0.8122    +0.0096
```

### The separation gap is 1.5 percentage points

The worst legitimate question scores **0.7968**. The best *completely unrelated*
question — «ما هي أفضل مطاعم مسقط؟» — scores **0.7816**. Everything Daleel must accept
and everything it must refuse is compressed into a 0.015-wide band.

This is precisely the D2 hazard the project context predicted, now **measured rather
than asserted**. Its consequence needs a decision before D2 runs:

> **A single absolute threshold is a fragile basis for the D6 refusal path.**
> Set it at 0.79 and a real question gets refused. Set it at 0.78 and restaurant
> questions get answered.

The distributions will shift on the real corpus, but the *compression* is a property of
e5 and will not go away.

Options to weigh at D2 (**none of this is built yet**):

- score the **margin** between top-1 and the mean of the rest, instead of an absolute floor
- lean harder on **D6's authority registry** — a deterministic keyword check that does not
  depend on this gap at all
- treat the threshold as one signal of two, rather than the sole gate

### On the E5 prefixes

`intfloat/multilingual-e5-*` is asymmetric and expects literal prefixes:
`"query: "` on questions, `"passage: "` on documents. Omitting them raises nothing —
it silently costs retrieval quality, and would do so *after* D2 sets a threshold and D7
publishes an accuracy figure, corrupting both with no error in the logs.

The ablation shows correct prefixes give the best gap and swapped give the worst, so the
direction holds — but on a 6-passage corpus the effect is modest and should not be
overclaimed. The prefixes are implemented correctly and enforced by tests regardless;
that is the model's documented design.

### One MISS is a curation lesson, not a model problem

«تجديد السجل التجاري» retrieved *commercial registration* instead of *licence renewal*,
because the two stand-in passages overlapped heavily.

> **For the curation team:** two services that read alike will be indistinguishable to
> retrieval. Each `##` section needs to be genuinely distinct.

## 4. The stale-index tripwire fired for real

Importing retrieval against the untouched Omantel index:

```json
{"level":"ERROR","message":"rag_index_dim_mismatch","index_shape":[304,384],
 "expected_dim":768,"hint":"stale index - re-run scripts/build_index.py"}
```

`retrieve()` returned `[]` rather than scoring garbage. An index built by a different
embedding model has a different width; without this check the mismatch surfaces either
as an opaque NumPy shape error at request time or — if widths happen to agree — as
silently meaningless similarity scores. That is the failure mode that would have
quietly poisoned both D2's threshold and D7's accuracy number.

## 5. D3 — Arabic normalization

One function, `normalize_arabic()`, called from **both** the index path and the query
path. Writing it twice is exactly how those paths silently diverge.

**Structural (always on):** NFKC (folds presentation forms back to letters), tashkeel,
tatweel, invisible joiners, Arabic-Indic → ASCII digits, whitespace collapse.

**Orthographic (toggleable, default on):** `أ إ آ ٱ → ا`, `ة → ه`, `ى → ي`.

The split is deliberate. Orthographic folding is unambiguously correct for lexical
matching, but this stack now uses a **dense multilingual encoder**. Folding absorbs real
user typing variance *and* hands the tokenizer spellings it never saw in training. Which
effect wins is an empirical question about Arabic — so it is a flag, and **D7 answers
it** by running the evaluation set both ways. Both sides read the same default, so the
paths cannot drift while that experiment runs.

**Normalization applies to text that gets embedded, never to text that gets stored.**
`chunks.json` keeps the original readable Arabic, because that is what goes into the
generation prompt and what a human proofreads.

## 6. $0 verification

Nothing points at a paid service. Embedding weights download free and need no token.
Generation defaults to Gemini's free tier.

Two cost risks, both documented in `.env.example`:

1. **Create the Gemini key in a project with no billing account attached.** A key from a
   billing-enabled project bills at paid rates past the free quota instead of rejecting
   the request. This is the only way this project accidentally costs money.
2. Free-tier prompts and responses may be used to improve Google's products. The corpus
   is public government information, so this is low-risk — but it is a knowing choice.

### Demo risk: free-tier rate limits

Free tier is roughly 10–15 RPM. Each turn currently costs **2 LLM calls** (route +
generate) and will cost **3** once D4's clarifying layer lands. A 5-question demo is
~15 calls.

`API_POLICY` was left at 1/2/4/8s deliberately. 15 seconds absorbs transient 5xx and
connection blips; it **cannot** clear a per-minute quota, which needs ~60s. Widening the
tail would mean up to a minute of silence mid-demo, which is worse than failing fast.
**Rate limiting is a D9 demo-planning problem, not a backoff problem.**

`RateLimitError` is now matched both by status (429) and by class name, so a rate limit
can never be misclassified as terminal.
