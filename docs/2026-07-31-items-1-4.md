## 0. Why this work happened in this order

The previous report measured e5's similarity behaviour on Arabic and found the
in-corpus and out-of-corpus score distributions separated by only **0.0153** — the
worst legitimate question scored 0.7968, the best completely unrelated one scored
0.7816.

That finding redefined D2. It is no longer "sweep for a threshold," because no single
absolute score can separate distributions that overlap that tightly, and tuning cannot
create a gap that is not there. D2 became a **three-layer gate**:

| Layer | Mechanism | Status |
|---|---|---|
| **L1** | Authority registry as a deterministic pre-gate, before embedding | **built (item 4)** |
| **L2** | Similarity as a weak signal — margin, not an absolute floor | deferred to real corpus |
| **L3** | Generation verifies its own grounding, `confidence: high\|partial\|none` | next |

D6 was therefore **promoted ahead of D2**: the registry is buildable today because it
needs the list of covered authorities and their Arabic name variants, not the documents
themselves. D2's tuning and D7's accuracy figure are explicitly deferred until the real
corpus lands — those numbers get quoted to judges and must not come from fixtures.

## 1. Item 1 — markdown loader + `##` header chunking

**New:** `src/chatbot/rag/markdown_corpus.py`
**Rewritten:** `scripts/build_index.py` — now takes `--fixtures`, `--pdf`,
`--source-dir`, `--out-dir`

Character-window chunking (500 chars / 100 overlap) is **not** ported to the markdown
path. It sliced fee tables and step lists in half, producing chunks that were
individually meaningless. A curated `##` section is already the right unit: one topic,
written to be read on its own. The PDF+OCR route survives behind `--pdf` as the
documented path to scale.

### The design point worth defending

**Stored text and embedded text are deliberately different.**

A section headed «الرسوم» contains nothing that identifies whose fees these are, so it
is effectively unretrievable on its own. What gets **embedded** is:

```
الجهة | الخدمة | ## القسم
<section body>
```

What gets **stored** in `chunks.json` stays clean Arabic — because that is what reaches
the generation prompt and what a human proofreads. Folding document context into the
stored text would degrade the answer to buy nothing.

### Validation behaviour

| Condition | Result |
|---|---|
| Missing required front-matter field | **build fails**, names the field and the file |
| `source_url` is not a full URL | **build fails** |
| Malformed YAML | **build fails**, names the file |
| `verified_by: PENDING` | warns — nobody has checked these facts |
| `##` section long enough for e5 to truncate | warns — silent truncation is invisible otherwise |
| `README.md` / `_draft.md` alongside corpus | skipped by name |

Documentation files are skipped **by name**, not by "does it have front-matter?" — so a
real service file with broken front-matter still fails loudly rather than being quietly
ignored. A silently-skipped service is one Daleel will deny having while the file sits
right there in the directory.

## 2. Item 2 — the corpus delivery contract

**New:** `docs/CORPUS_SPEC.md`, `docs/corpus-example/rop-passport-renewal.md`

The `##` headings are standardised — `الفئة المستهدفة`, `المستندات المطلوبة`, `الخطوات`,
`الرسوم`, `المدة المتوقعة`, `أين تتم المعاملة`, `ملاحظات` — because they map directly
onto D5's answer-card fields. Using different headings degrades the output, and the spec
says so explicitly.

### The example file uses placeholders, on purpose

Every factual slot in the worked example — fees, durations, document lists, validity
periods — is written as `‹...›` rather than a realistic value.

> **A template containing invented government fees is exactly how fabricated data
> reaches a citizen.** Someone copies the file, misses a line, and Daleel states a wrong
> fee with a confident official citation. The example teaches *shape*; the official page
> supplies *facts*.

The file also sits outside `data/source_docs/` so it can never be indexed, carries
`verified_by: UNVERIFIED_EXAMPLE`, and opens with an HTML banner that renders invisibly
in a markdown previewer but is unmissable in the source.

### Deliberate ambiguity is kept

Commercial registration and licence renewal are **not** separated. Real citizens confuse
them, and that collision is the designed trigger for D4's clarifying question:

> «هل تقصد تسجيل سجل تجاري جديد، أم تجديد رخصة قائمة؟»

Both files are written distinctly, but the overlap stays. The right handling of an
ambiguous question is to ask, not to guess.

## 3. Item 3 — fixtures, quarantined

**New:** `data/fixtures/` — six stand-in service files, all carrying `fixture: true`.

The guard is enforced, not advisory:

```
REFUSING TO BUILD: fixture content cannot be written to the real index at
  .../data/index.
  Offending files: mociip-commercial-registration.md, mociip-licence-renewal.md, ...
  Fixtures are invented stand-in content. Use --fixtures to build them into
  data/fixtures/index/ instead.
```

Fixtures are invented. If they reached `data/index/` the app would answer citizens from
made-up government procedures, and any accuracy figure measured against them would be
meaningless while looking legitimate. Cheap check, catastrophic failure mode.

**Added `INDEX_DIR` to config.** Without it, "develop against fixtures" was not actually
possible — nothing could point the running app at the fixture index.

```bash
python scripts/build_index.py --fixtures        # -> data/fixtures/index/
INDEX_DIR=data/fixtures/index python -m chatbot.app
```

The seven Omantel source files and the stale 384-dim index artifacts are deleted from

## 4. Item 4 — D6 Layer 1: the authority registry

**New:** `src/chatbot/agent/` package, `src/chatbot/agent/registry.py`,
`data/registry/authorities.json`

The `agent/` directory is the literal answer to the panel question *"where is the
agent?"* — it holds the layers that **decide**, as opposed to the layers that fetch.

### Coverage

| | Count |
|---|---|
| Covered authorities | 2 (ROP, MoCIIP) |
| Covered services | 6 |
| Known-but-uncovered authorities | 13 |

Everything the module knows comes from JSON. Extending coverage means editing that file
and adding corpus files — no Python changes. That claim is made to the panel; the
data-driven design is what keeps it honest.

Matching runs on **D3-normalised text on both sides**, so the JSON does not enumerate
`ة`/`ه` or hamza spellings — D3 already folds them. Variants shorter than 4 characters
are ignored to avoid false positives.

### The three verdicts

| Verdict | Meaning | Action |
|---|---|---|
| `COVERED` | a covered authority or service was named | proceed to retrieval |
| `UNCOVERED_AUTHORITY` | a **different**, known Omani authority was named | refuse now, name it, promise coverage |
| `UNKNOWN` | nothing matched either way | **proceed to retrieval anyway** |

### Why `UNKNOWN` must not refuse

This is the critical property of the layer, and it was validated by accident in testing:

```
Q: هل يلزم الفحص الفني لتجديد الملكية؟
   L1 verdict : unknown
   L2 0.8271  rop-vehicle-registration-renewal / المستندات المطلوبة
```

The phrasing «تجديد الملكية» was not a listed variant, so L1 had no opinion — and L2
then retrieved exactly the right service. **A gate that refused whatever it failed to
recognise would have rejected a perfectly valid citizen question.** Keyword matching has
no opinion about phrasings nobody thought to list, and "no opinion" must never become
"no".

The missing variants have since been added, but the fall-through is what made the miss
harmless instead of visible to a citizen.

### D6's two refusal paths stay distinct

| Path | Trigger | Response |
|---|---|---|
| 1 | authority covered, this procedure not found | "I don't have this specific service" **+ the official portal URL** |
| 2 | a different known authority named | «... ليست ضمن قاعدة معرفتي بعد — سيتم إضافتها قريبًا» **+ what Daleel does cover** |

Collapsing both into one generic apology would lose information the citizen is owed.
A test asserts the two messages differ, that path 1 hands over a URL, and that path 2
promises future coverage.

## 6. Two things to flag

### A retrieval-quality wrinkle

For «ما هي رسوم تجديد البطاقة الشخصية؟» the `الخطوات` section outranked `الرسوم`
(0.8738 vs 0.8605). A fees question ideally ranks the fees section first.

Both sections reach generation at `k=3`, so the answer is still grounded and this is not
currently harmful. It is something for **D7 to measure on the real corpus** — not worth
chasing against fixtures.

### A correction to my own spec

`CORPUS_SPEC.md` initially stated that a blank line before the front-matter is an error,
while the loader tolerated it. **I changed the spec, not the code.**

A leading blank line has exactly one possible interpretation, and failing the build on it
would generate errors that teach the curation team nothing under deadline. Strictness is
spent where it catches real mistakes: content *above* the front-matter is still rejected,
because that means the author misunderstood the format and the fields they believe they
set would be silently ignored.
